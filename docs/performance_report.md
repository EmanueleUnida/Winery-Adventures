# Performance report

Generated by `benchmark.py`. All numbers are measured on the machine described below.

## Setup

- OS: Windows-10-10.0.26200-SP0
- CPU: Intel64 Family 6 Model 154 Stepping 3, GenuineIntel (12 logical cores), RAM: 19.7 GB
- Python 3.11.16, Numba 0.67.0, Polars 1.44.2, NumPy 2.4.6
- Dataset: 100,000 sensor readings; 300,000 rows after the grape variety transformation

## 1. Stress formula: plain Python vs Numba

The formula compares every pair of readings, so its cost is O(n^2). Best time over several runs, without compilation time.

| Readings (n) | Plain Python (s) | Numba (s) | Speedup |
|---:|---:|---:|---:|
| 250 | 0.013 | 0.00007 | 187x |
| 500 | 0.053 | 0.00027 | 193x |
| 1,000 | 0.210 | 0.00109 | 192x |
| 2,000 | 0.848 | 0.00429 | 198x |
| 4,000 | 3.321 | 0.01678 | 198x |

- Numba compiles the function at the first call: 0.57 s, paid once per process.
- With n = 4,000 readings Numba is 198 times faster than plain Python.
- Doubling n from 2,000 to 4,000 multiplies the Numba time by 3.9 (about 4 is expected for an O(n^2) algorithm).

## 2. Full pipeline on the whole dataset

| Stage | Time (s) | Peak memory (MB) | Memory increase (MB) |
|---|---:|---:|---:|
| Load TSV files | 0.023 | 184 | 5 |
| Transformations | 0.047 | 247 | 62 |
| Stress, n_jobs=1 | 1.102 | 273 | 27 |
| Stress, n_jobs=-1 (12 cores) | 0.219 | 331 | 58 |

Peak memory is the resident memory (RSS) of the whole process, sampled while the stage runs; it includes the data loaded by the previous stages.

- Transformations plus stress score take about 0.27 s for the whole dataset.
- The stress is computed independently for each tank. With Joblib the run with n_jobs=-1 is 5.02x faster than with n_jobs=1.
- Joblib uses threads (`require="sharedmem"`): the Numba function is compiled with `nogil=True`, so the threads really run in parallel and no data is copied between processes.

## Conclusions

Compiling the O(n^2) stress formula with Numba is what makes the analysis practical: the same algorithm is about 198 times faster than plain Python. Parallelising over tanks with Joblib gives a further gain (5.02x), limited by the number of cores and by the tanks with more readings.
